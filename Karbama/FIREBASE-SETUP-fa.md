# راهنمای وصل‌کردن کارباما به دیتابیس واقعی (Firebase) — ۵ دقیقه

تا وقتی این کارها را انجام نداده‌ای، اپ در **حالت نمایشی** کار می‌کند: همه‌ی اطلاعات (آگهی‌ها، متقاضیان، عکس‌ها، پسندیده‌ها) فقط روی **خود گوشی** ذخیره می‌شود و بین گوشی‌ها مشترک نیست. با انجام این ۵ مرحله، همه‌چیز روی **Firebase** می‌رود و کارجو و مدیر همه‌ی داده‌ها را می‌بینند.

---

## مرحله ۱ — ساختن پروژه در Firebase

1. به <https://console.firebase.google.com> برو و با حساب گوگل خودت وارد شو.
2. **Add project** → یک نام بده (مثلاً `karbama`) → Continue → (می‌توانی Google Analytics را خاموش کنی) → **Create project**.

## مرحله ۲ — اضافه‌کردن اپ اندروید و گرفتن فایل `google-services.json`

1. در صفحه‌ی پروژه، روی آیکون **Android** بزن.
2. **Android package name** را دقیقاً این بگذار:
   ```
   com.karbama.app
   ```
   (اسم دلخواه نگذار — باید با `applicationId` برنامه یکی باشد.)
3. Nickname و SHA-1 لازم نیست → **Register app**.
4. فایل **`google-services.json`** را دانلود کن و آن را دقیقاً اینجا بگذار:
   ```
   Karbama/app/google-services.json
   ```
5. در برنامه دوباره Build بزن:
   ```bash
   cd Karbama
   ./gradlew :app:assembleRelease
   ```
   ✅ از این لحظه اپ خودش «حالت متصل» می‌شود؛ هیچ کد دیگری لازم نیست.

## مرحله ۳ — روشن‌کردن سه سرویس

در منوی چپ Firebase Console:

| سرویس | کار | تنظیم لازم |
|---|---|---|
| **Authentication** | ورود کارجو (ناشناس) و ورود مدیر (ایمیل + رمز) | Get started → Sign-in method → **Anonymous** را Enable کن و **Email/Password** را Enable کن |
| **Firestore Database** | دیتابیس اطلاعات (آگهی‌ها، متقاضیان، پسندیده‌ها، درخواست‌ها) | Create database → **Production mode** → یک منطقه (مثلاً `eur3`) |
| **Storage** | دیتابیس عکس‌ها و ویدیوها | Get started → Production mode → همان منطقه |

## مرحله ۴ — ساختن حساب مدیر

1. **Authentication → Users → Add user**:
   - Email: ایمیل خودت (مثلاً `admin@karbama.com`)
   - Password: یک رمز قوی
2. بعد از ساختن، روی همان کاربر بزن و **User UID** را کپی کن (چیزی مثل `aB3dEf…`).
3. در **Firestore → Data → Start collection**:
   - Collection ID: `admins`
   - Document ID: **همان User UID** که کپی کردی
   - یک فیلد دلخواه اضافه کن: `role` = `admin` → Save.
4. **Storage → Rules**: در فایل `storage.rules` (همین پوشه) جای `ADMIN_UID_1` **همان User UID** را بگذار و متن را در Console جای‌گذاری و **Publish** کن.

> ⚠️ اگر این کار را نکنی، آپلود عکس/ویدیوی آگهی توسط مدیر خطای «permission denied» می‌دهد.

## مرحله ۵ — Publish کردن قواعد امنیتی

دو فایل آماده در همین پوشه هست؛ محتوایشان را در Console جای‌گذاری و Publish کن:

| فایل | کجا |
|---|---|
| `firestore.rules` | Firestore Database → Rules |
| `storage.rules` | Storage → Rules |

همین. حالا اپ را نصب کن: کارجو ثبت‌نام می‌کند (عکس پاسپورت + عکس قدی داخل Storage و پروفایل داخل Firestore می‌رود) و مدیر با **ایمیل و رمز همان حساب Firebase** وارد می‌شود.

---

## کدام داده کجا ذخیره می‌شود؟ (خلاصه‌ی فنی)

| داده | محل ذخیره در حالت متصل |
|---|---|
| آگهی‌ها | Firestore → collection **`jobs`** → `jobs/{jobId}` |
| عکس/ویدیوی آگهی | Storage → `jobs/{jobId}/job_….jpg|mp4` و `poster_….jpg` (لینکش در Firestore) |
| پروفایل متقاضی | Firestore → `applicants/{uid}` |
| عکس پاسپورت و عکس قدی | Storage → `applicants/{uid}/id_card.jpg` و `body_photo.jpg` |
| **پسندیده‌ها** | Firestore → `likes/{applicantId}_{jobId}` |
| **درخواست‌های ارسالی** | Firestore → `applications/{applicantId}_{jobId}` |
| فهرست مدیران | Firestore → `admins/{adminUid}` |
| زبان، ورود دومرحله‌ای، کارت کارگزار | روی خود گوشی (SharedPreferences) — عمداً روی سرور نمی‌رود |

**در پنل مدیر:** با باز کردن هر متقاضی، دو کارت تازه می‌بینی — **«❤ پسندیده‌ها»** و **«📨 درخواست‌های ارسالی»** — که زنده از حساب همان کاربر روی سرور خوانده می‌شوند.

---

## چند نکته‌ی مهم

- **ورود کارجو با یوزرنیم/پسورد** است (نه ایمیل). به همین دلیل شناسه‌ی هر متقاضی در Firestore، همان `uid` ساخت‌شده در زمان ثبت‌نام روی همان گوشی است. اگر کاربر روی **گوشی تازه‌ای** وارد شود، پروفایلش را می‌بیند ولی نوشتن پسندیده/درخواست برای او محدود می‌شود؛ برنامه در این حالت **محلی ذخیره می‌کند** و خطا نمی‌دهد.
  - راه‌حل کامل (اختیاری، برای بعد): در مرحله‌ی ورود، حساب ناشناس گوشی را با ایمیل کاربر **Link** کنید یا برای هر کارجو یک حساب Firebase بسازید تا هویت روی همه‌ی گوشی‌ها یکی شود.
- **بدون ایندکس ترکیبی:** کوئری پسندیده‌ها/درخواست‌ها فقط «برابری» دارد و مرتب‌سازی در خود برنامه انجام می‌شود؛ پس Firebase از تو ایندکس ترکیبی نمی‌خواهد و کار تمام است.
- **فشرده‌سازی عکس‌ها:** قبل از آپلود، بُعد عکس حداکثر ۱۲۸۰ پیکسل و کیفیت JPEG = ۸۲ می‌شود (`Config.MAX_PHOTO_DIM/PHOTO_QUALITY`).
- **سقف‌های رایگان Firebase** برای شروع کافی است: Firestore 1GB، Storage 5GB، و ۱۰GB ترافیک ماهانه (پلن Spark).
- **در حالت نمایشی (بدون `google-services.json`)** هیچ‌چیز به اینترنت فرستاده نمی‌شود؛ دموی HTML هم اطلاعاتش را در `localStorage` همان مرورگر نگه می‌دارد.
